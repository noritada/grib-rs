# Direct decoder construction accepts short section buffers that can cause panics

## Summary

Applications that pass externally supplied section buffers directly to `Grib2SubmessageDecoder::new()` may panic during construction or subsequent decoding if required bytes in Sections 6 or 7 are missing.

## Affected usage and impact

The affected usage is direct construction of a decoder from separately obtained Section 5, 6, and 7 byte vectors. This can occur in applications with their own section extraction or transport layer.

With an otherwise valid Section 5:

- A Section 6 buffer shorter than six bytes can panic during `new()`.
- A Section 7 buffer shorter than five bytes can be accepted by `new()` and later panic when a decoding path accesses its payload. Not every decoding path accesses that payload.

Both APIs return `Result`, but these failures occur before an error is returned.

A panic does not necessarily cause denial of service. Depending on the application's panic handling and build settings, it may interrupt a processing thread or terminate the process. This can become a denial-of-service vulnerability when an attacker can supply input to the affected operation and the resulting failure disrupts service for legitimate users. A failure confined to the attacker's request does not by itself establish service-wide denial of service; the impact depends on how the application isolates failures and maintains processing capacity.

If only trusted application code constructs the supplied buffers, their invalidity alone does not establish an external attack path.

No confidentiality or integrity impact has been established.

## Scope limitations

The normal decoding path through `grib::from_reader()` is not affected by this issue. Its reading and validation prevent the undersized Section 6 and Section 7 buffers described here from reaching the decoder. This issue affects direct calls to `Grib2SubmessageDecoder::new()` with separately supplied section buffers.

A short Section 5 buffer already returns a parsing error in the tested case. Unknown template numbers in Section 5 are covered separately by [GHSA-6j96-629m-89w4](https://github.com/noritada/grib-rs/security/advisories/GHSA-6j96-629m-89w4).

## Mitigation and remediation

Upgrade the `grib` crate to version **0.18.6**, which fixes this issue.

## Version and publication status

The final version of [GHSA-v8g4-j727-859g](https://github.com/noritada/grib-rs/security/advisories/GHSA-v8g4-j727-859g). The fix is confirmed in `grib` version **0.18.6**. Affected versions of `grib`: `>= 0.12.0, < 0.18.6`.
